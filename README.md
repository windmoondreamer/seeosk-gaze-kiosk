# SeeOSK — macOS 시선 키오스크 v0.1

실행 앱: **`~/Downloads/SeeOSK.app`**

## 사용 순서

1. Finder에서 `SeeOSK.app`을 더블클릭합니다. 터미널 없이 메가커피 주문 연습 화면이 열립니다.
2. 사용할 창 크기와 위치를 먼저 정합니다. 필요하면 **전체 화면**을 누릅니다.
3. 오른쪽 위 **캘리브레이션**을 누릅니다. 처음 뜨는 macOS 카메라 권한 요청을 허용합니다. 카메라 선택은 오른쪽 패널에서 할 수 있습니다.
4. 머리는 편안하게 고정하고, 화면에 나타나는 9개 점을 눈동자로 따라봅니다. 이어지는 3개 점으로 보정 결과를 확인합니다. 눈을 감거나 얼굴·머리 위치를 벗어나면 수집을 기다립니다.
5. 보정 완료 후 실제 macOS 마우스가 시선을 따라 움직입니다. 별도 확인점의 평균/95% 오차를 오른쪽에 표시합니다. 오차가 커도 이동은 시작하며, 재보정을 권장합니다.
6. 키오스크 화면 위 파란 점이 추정 시선, 초록 테두리가 바라보는 선택 영역입니다. 기본 상태는 실제 마우스 이동이며 자동 선택은 기본으로 켜져 있습니다. **Space**를 누르면 현재 영역을 선택합니다. **0.9초 바라보면 선택**을 켜면 머무름으로도 선택할 수 있습니다.

**Esc**: 보정 중 취소, 일반 화면에서는 마우스 이동 일시정지. 카메라까지 끄려면 **카메라 끄기**. 앱을 닫으면 카메라 엔진도 종료합니다.

같은 메뉴에 시선을 계속 두어도 자동 선택은 한 번만 합니다. 다른 위치를 0.3초 이상 바라봐야 다시 선택합니다. 얼굴을 놓치거나 최근 시선 데이터가 0.35초 넘게 없으면 마우스 이동을 멈추고 화면 시선 점과 선택을 해제합니다.

## 두 화면과 두 영역 탐지 방식

- **메가커피**: SYiee/KIOSK의 로컬 HTML 재현본. 메뉴 선택과 모의 결제 화면을 사용할 수 있습니다. 기본 **웹 버튼 위치**는 실제 클릭 핸들러의 화면 사각형을 읽습니다. YOLO 결과가 아닙니다.
- **학습 화면**: 사용자가 준 `Downloads/images`의 PNG 800장. 제공한 `best.pt`로 영역을 탐지합니다. 이미지이므로 영역을 선택해도 주문 화면으로 전환되지는 않습니다.
- **학습 모델로 탐지 (YOLO)**: 메가커피 웹뷰의 현재 화면도 앱 안에서 캡처하여 추론할 수 있습니다. 화면 변경 시 다시 탐지합니다. 단, 검증한 메가커피 화면에서는 confidence 0.35 기준 **0개**를 탐지했습니다. 실제 매장 화면에 적용하려면 추가 학습·검증이 필요합니다.

## 입력 자료와 구현

- 기존 `../gaze_mouse/camera_mouse.py`의 홍채 특징 추출 및 1€ 필터를 `engine/legacy_gaze.py`로 보존하여 사용합니다.
- 눈동자 위치 두 특징으로 2차 회귀를 학습합니다. 릿지 강도는 9개 보정점의 leave-one-out으로 선택하고, **별도 3점의 오차**로 정확도를 표시합니다.
- 정확도 통과 기준: 평균 오차 ≤ `min(90px, 화면 대각선×0.06)`, 95% 오차 ≤ `min(150px, 대각선×0.11)`. 이는 이 시제품의 운용 기준이며 표준 정확도 인증이 아닙니다.
- `seeosk_v2_recheck_20260918_144929_153011/train/weights/best.pt`를 `assets/best.pt`에 포함했습니다. 이 가중치는 화면의 `clickable` 영역 탐지용입니다.
- `assets/training_evaluation.json`에 원래 학습 평가를 보존했습니다. 원래 테스트는 합성 UI의 무작위 분할이며 시선 정확도를 측정한 자료가 아닙니다.
- Swift AppKit + WKWebView가 UI를 표시하고, Python/MediaPipe/OpenCV 엔진과 JSON 메시지로 연결됩니다. 시선과 영역은 웹뷰의 CSS 픽셀 좌표를 사용합니다. CoreGraphics로 실제 시스템 커서를 이동합니다. 앱이 활성 상태인 동안만 움직이며 좌표는 앱의 콘텐츠 영역에 한정됩니다.

## 보정과 저장

- 프로파일: `~/Library/Application Support/SeeOSK/profiles/`
- 엔진 로그: `~/Library/Application Support/SeeOSK/engine.log`
- 카메라 원본 영상과 얼굴 프레임은 파일로 저장하지 않습니다. 미리보기는 메모리 안에서만 전달합니다.
- YOLO용 키오스크 스냅샷은 임시 PNG로 만들고 추론 후 삭제합니다.
- 카메라 ID, 창 위치·크기, 화면 배율이 일치하는 프로파일만 재사용합니다. 카메라나 본인의 자세를 옮긴 경우에는 직접 다시 보정해 주세요.
- 카메라 권한이 거절되면 앱의 **카메라 권한 설정 열기** 버튼을 이용합니다. macOS가 재실행을 요구하면 앱을 다시 엽니다.

## 확인한 범위

- 보정 회귀, 독립 확인점, 오차 초과 거부, 얼굴 이탈 시 수집 대기, 프로파일 저장·취소·무효화: Python 테스트로 검증합니다.
- 실제 macOS 앱 실행 및 WKWebView의 메뉴 선택, 800장 목록, YOLO 추론 연결, 보정 UI, 시선 좌표 주입, 반복 선택 방지 등: `verification/native-smoke.json`.
- 제공된 첫 학습 이미지: confidence 0.35에서 16개 영역. 메가커피 스냅샷: 0개 영역. 이 숫자는 정답 대비 정확도 측정이 아닙니다.
- FaceLandmarker 모델 로드 및 빈 영상에서 얼굴을 오검출하지 않는 것을 macOS 영상 처리 환경에서 확인했습니다.
- 실제 사용자 눈, 안경·조명·사용 거리 조건에서의 시선 정확도와 전체 주문 성공률은 아직 측정하지 않았습니다. 자동 UI 검증의 시선 좌표는 테스트 입력입니다.

## 개발과 빌드

이 Mac에서 바로 실행하는 로컬 개발 앱입니다. Python 실행 환경은 이 프로젝트의 `.venv`를 사용하므로 **`seeosk_mac` 폴더를 이동·삭제하면 앱 엔진이 실행되지 않습니다.** 다른 Mac용 독립 설치 패키지는 아직 만들지 않았습니다.

```sh
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
python3 build.py
```

`build.py`는 `dist/SeeOSK.app`을 빌드하고 `~/Downloads/SeeOSK.app`에 실제 앱 파일을 복사합니다. 실행 환경 버전은 `requirements.lock.txt`에 기록했습니다. 가상환경은 `uv`로 관리하므로 `pip` 모듈이 없어도 됩니다.

## 커서 안정화 (2026-09-28)
최근 5개 좌표의 중앙값, 시간 기반 평활화, 6px 미세 이동 억제를 적용합니다. 커서는 메뉴 중앙에 고정하지 않습니다. 메뉴 선택은 180ms 확인 후 활성화하며 선택 진행률은 0.3초 이하의 짧은 이탈에서 유지합니다. 이탈·감지 끊김 시간은 누적하지 않으며 다른 메뉴를 180ms 바라보면 새 선택으로 전환합니다. 화면 밖 추정은 경계로 제한한 후 필터에 전달합니다. Space로 즉시 선택하거나 자동 선택을 켜서 0.9초 유지합니다.
보정은 9점 + 확인 3점, 점당 준비 0.45초 + 유효 수집 최소 0.65초입니다. 명목 최소 약 13초이며 프레임 부족·얼굴 이탈·재시도 시 길어집니다.
실제 사용자 로그에서 이전 보정 평균 오차 342.6px를 확인했습니다. 안정화는 편향 오차를 교정하지 않으며 새 보정의 실제 정확도는 미검증입니다.

## 버튼 선택 시험 모드
앱이 열린 상태에서 **버튼 선택 · F8**을 누르면 화면의 실제 웹 버튼을 최대 4개의 큰 카드로 표시합니다. 왼쪽/오른쪽 또는 위/아래 키로 이전/다음, Enter/Space로 후보 선택 후 한 번 더 눌러 실행, Esc로 확인 취소/닫기입니다. 카메라·보정 없이 작동하며 시선 추적은 일시정지합니다. Mac 내장 키보드는 시스템 설정에 따라 Fn+F8이 필요할 수 있습니다.

검증 범위: WKWebView 키 핸들러에 입력을 주입하여 화면 열기, 커피프라페 후보 이동, 확인, 주문까지 시험. 실제 USB 버튼/Pico 연결·펌웨어·CDC 이벤트 수신·장치 연결 시 자동 실행은 미구현/미검증입니다. 기존 설계의 CDC NEXT/SELECT 이벤트를 이 기능에 연결하는 어댑터가 추가로 필요합니다. HID 키보드로 위 키를 보내는 장치 역시 실물 확인이 필요합니다.

이 기능은 로컬 HTML 키오스크에서만 동작합니다. 임의 매장 키오스크에 USB를 꽂는 것만으로 화면을 읽거나 UI를 교체할 수 있다는 뜻이 아닙니다. 실제 도입은 호스트 보조 앱 설치 및 메뉴/입력 연동 확인이 선행되어야 합니다.
