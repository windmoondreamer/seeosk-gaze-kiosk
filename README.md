# SeeOSK — 고개로 조작하는 키오스크

## 실행

실행 앱은 `11_창의문제해결/배포/macOS/SeeOSK.app`입니다. 더블클릭하면 원래 메가커피 주문 화면이 열립니다.

1. **카메라 켜기**를 누릅니다. 처음에는 macOS가 표시하는 카메라 사용 허용 창에서 허용합니다.
2. 정면을 보고 약 0.7초 멈춥니다. 점을 따라보는 캘리브레이션은 없습니다. 이어서 약 3초 동안
   다문 입을 기준선으로 잡습니다. 이 사이에는 입을 벌려도 선택되지 않습니다.
3. 고개로 포인터를 옮기고 **입을 벌려** 선택합니다. Space로도 선택할 수 있습니다.
4. **포인터 감도**는 왼쪽 슬라이더로 조절합니다. 기본값 25%이며, 낮출수록 같은 거리를 가는 데
   고개를 더 크게 움직여야 하는 대신 천천히·정확하게 움직입니다. 화면 가장자리에 닿지 않으면
   값을 올리세요.
5. 자세를 바꿨으면 **중앙 다시 맞추기**를 누릅니다. 입벌림 기준선도 함께 다시 잡습니다.
   Esc는 일시정지입니다.

macOS 머리 포인터 기능을 켤 필요가 없습니다. 머리 포인팅은 이 앱이 직접 구현합니다. 앱 내부의
얼굴 랜드마크 추적으로 커서를 움직이고 선택합니다. 눈동자 추정값은 사용하지 않습니다. 카메라
접근을 이전에 거부한 경우에는 OS 보안상 앱이 임의로 다시 허용할 수 없습니다.

## 패키지와 소스

- `packaging/build_macos.sh`: Python 추적 엔진과 의존성을 묶은 후 Swift/WebKit 앱을 빌드합니다.
- `packaging/build_windows.py`: Windows x64 휴대형 폴더를 만듭니다. 이전 독립 포인터 실험판용입니다.
- `build.py`: 원래 키오스크 화면을 빌드하고 배포 폴더의 SeeOSK.app을 교체합니다. 번들 엔진이 없으면 개발용 Python 환경을 사용하므로, 배포에는 위 패키징 스크립트를 사용합니다.
- `engine/head_pointer.py`: 정면 기준 수집, 머리 좌표 변환, 안정화, 감도 배율.
- 입벌림 클릭은 `legacy_gaze.ThresholdDetector('jawopen')`를 그대로 씁니다. 자동 기준선 3초,
  이중 임계값, 0.12초 유지, 0.9초 불응기입니다.
- `engine/worker.py`: 카메라/모델과 앱 사이의 JSON 통신.
- `engine/onnx_detector.py`: 클릭 영역 모델을 onnxruntime으로 실행합니다. 배포 번들에는 torch와 ultralytics를 넣지 않습니다.
- `native/main.swift`: 앱 창과 카메라 권한 요청, 번들 엔진 실행.
- `web/`: 주문 화면과 메뉴 선택.
- `engine/standalone.py`, `engine/legacy_gaze.py`: 이전 독립 포인터 실험 코드. 현재 배포 앱의 UI 진입점이 아닙니다. 얼굴 추적 유틸리티 일부는 공유합니다.

이번 고개 조작 키오스크 앱은 Apple Silicon macOS용입니다. 기존 Windows 패키지는 이전 독립 포인터 실험판이며 같은 키오스크 UI를 제공하지 않습니다. Windows 실기기 검증은 수행하지 않았습니다.

## 포인터 범위

**이 앱 안에서만**(기본) 모드는 SeeOSK 창 안에서만 포인터가 움직이고 앱 내부 메뉴를 클릭합니다.

**화면 전체** 모드는 디스플레이 전체에서 실제 시스템 커서를 움직이고, 입벌림이 실제 좌클릭으로
나갑니다. 다른 앱도 조작할 수 있습니다. 이때 고개 범위는 창이 아니라 디스플레이 크기에 대응합니다.

권한은 두 가지가 다릅니다. 실측 결과 **커서 이동은 손쉬운 사용 권한 없이도 동작합니다**
(`AXIsProcessTrusted=false` 상태에서 화면 네 방향 좌표로 오차 0px 이동 확인). 반면 **클릭은
손쉬운 사용 권한이 필요합니다.** 권한이 없으면 클릭을 보내지 않고 설정 바로가기를 띄웁니다.

macOS 손쉬운 사용의 머리 포인터 기능 자체를 앱이 켜 주는 것은 불가능합니다. 설정 키
(`com.apple.universalaccess headMouseEnabled`)에 값을 써도 기능이 켜지지 않고, 데몬 재시작은
SIP가 막으며 공개 API도 없습니다. 그래서 그 기능에 위탁하지 않고 직접 구현했습니다.

`--pointer-check`로 커서 이동을, `--camera-check`로 카메라 열기를 앱 컨텍스트에서 진단할 수 있습니다.

## 감도와 입벌림 클릭

감도는 0.05~1.0 눈금이며 기본값은 0.25입니다. macOS 손쉬운 사용의 머리 포인터도 같은 0~1
눈금에 기본값 0.5를 쓰므로, 0.5에서 이전 배율이 그대로 나오고 0.25는 그 절반이 되도록
`gain = 2 × 감도`로 환산합니다.

주의할 점이 있습니다. macOS 머리 포인터는 상대 이동이지만 이 앱은 고개 각도를 화면 좌표에
그대로 대응시키는 절대 방식입니다. 그래서 같은 25%라도 체감이 다르고, 감도를 낮출수록 화면
가장자리에 닿는 데 필요한 고개 회전이 커집니다. 실제 사용자에서 가장자리 도달 가능 여부는
측정하지 않았습니다.

입벌림 클릭은 시작·중앙 다시 맞추기 직후 3초 동안 다문 입을 기준선으로 잡습니다. 그 3초간
입을 벌리고 있으면 벌린 상태가 평상시로 학습되어 클릭이 막히며, 중앙 다시 맞추기로 복구합니다.
이 동작은 테스트로 고정해 두었습니다.

## 클릭 영역 모델

배포 번들은 `assets/best.onnx`를 onnxruntime으로 실행합니다. 학습 산출물 `assets/best.pt`(YOLO26n,
SHA-256 `9ce8b8c5…`)는 저장소에만 두고 번들에는 넣지 않습니다. `best.onnx`는 그 가중치를
`imgsz=640, opset=17, nms=True`로 내보낸 것입니다.

이렇게 바꾼 이유는 크기입니다. torch와 ultralytics를 함께 묶으면 앱이 2.0GB가 되고, onnxruntime만
쓰면 529MB가 됩니다. jax·polars·scipy도 어느 코드 경로에서도 임포트하지 않아 함께 제외했습니다.
matplotlib은 mediapipe가 실제로 임포트하므로 남겨 두었습니다.

두 경로의 결과는 완전히 같지는 않습니다. 학습 화면 800장 전체를 대조한 결과 789장은 탐지 개수가
같았고, 11장(1.4%)에서 개수가 1~3개 달랐습니다. 일치한 박스들의 최저 IoU는 0.849였습니다.
차이 나는 박스는 대부분 confidence 0.35 임계값 근처였으나 0.469인 사례도 있었습니다.
`nms=False`로 내보내면 차이가 322장으로 오히려 커져 `nms=True`를 택했습니다.
학습 화면 탭은 연습·시연용이며, 이 정도 차이가 실제 사용성에 주는 영향은 측정하지 않았습니다.

## 검증과 한계

자동 검사는 메뉴 주문, 수량 변경, X 삭제, 커피 프라페, 정지 선택, 반복 주문 방지, 중앙 다시 맞추기와 창 크기 변경을 포함합니다. `verification/head-mode` 및 `verification/head-portable`에 결과를 기록합니다.

자동 UI 검사의 포인터 좌표는 테스트 입력입니다. 실제 사용자 고개 움직임에서의 정확도와 전체 주문 성공률은 별도 사용성 확인이 필요합니다. YOLO는 제공 학습 이미지에서 영역을 찾지만 메가커피 재현 화면에서는 탐지가 부족하므로 기본 메뉴 선택은 실제 웹 버튼 좌표를 사용합니다.

카메라 영상은 저장하거나 전송하지 않습니다. 키오스크 화면은 SYiee/KIOSK 재현본이며 실제 매장 결제와 연결되지 않습니다.
